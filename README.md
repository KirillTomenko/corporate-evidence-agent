# Corporate Evidence Agent

Локальный помощник для сотрудников, которым нужен ответ по корпоративному регламенту. В интерфейсе можно задать вопрос, раскрыть текст основания и найти его в исходном DOCX по имени файла и локатору. Если оснований недостаточно, сотрудник может передать вопрос в службу качества. При повторном обращении утверждённый экспертный ответ имеет приоритет, даже если регламент ещё обновляется.

MVP для хакатона «ИИкузница». Пример ниже работает на одном синтетическом документе.

## Архитектура

| Компонент | Роль |
|---|---|
| `evidence.py` | Разбирает DOCX через python-docx, индексирует абзацы и ячейки таблиц в SQLite FTS5. При чтении сверяет версию файла, позицию и текст фрагмента с оригиналом. |
| `agent.py` | Проверяет входные данные и необходимость уточнения, ищет утверждённый FAQ. При отсутствии FAQ выполняет лексический поиск с учётом области. Локальная модель выбирает цитату, код сверяет её с источником, затем модель проверяет черновик по найденным фрагментам. |
| `app.py` | Интерфейс Streamlit для вопросов, уточнений, просмотра оснований и регистрации обращений. |
| `quality.py` | Хранит обращения в отдельной базе SQLite. Предоставляет оператору CLI для просмотра очереди и утверждения ответа. |
| `quality_mail.py` | По желанию отправляет исходящее уведомление о зарегистрированном обращении через SMTP с TLS. |

## Требования

- Для инструкции ниже используйте Windows, PowerShell и Python 3.12. Проверенное окружение — Python 3.12.8 и SQLite 3.45.3 с FTS5. Нужна запись в каталоги `corpus/` и `data/` внутри копии проекта.
- Python-зависимости приложения — Streamlit 1.51.0 и python-docx 1.2.0. Для тестов дополнительно требуется pytest 9.1.1. Версии перечислены в `requirements.txt` и `requirements-dev.txt`.
- Для ответов по регламенту нужна установленная отдельно Ollama с локальной моделью GGUF. Клиент использует HTTP API на `127.0.0.1:11434`, методы `/api/show` и `/api/generate` с JSON Schema. Версия Ollama в проекте не закреплена. При первой установке нужен доступ к пакетам и весам модели.

## Локальный запуск

### 1. Подготовьте окружение

Откройте PowerShell в корне чистой копии репозитория, рядом с `app.py`. Все команды ниже выполняются из этого каталога. Активация виртуального окружения не требуется.

```powershell
$env:PYTHONUTF8 = '1'
$env:CEA_SMTP_ENABLED = '0'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. Создайте учебный документ и индекс

У индексатора фиксированный список имён файлов. Скрипт берёт разрешённое имя из `evidence.FILES` и создаёт документ с одним учебным абзацем. Выполните его один раз в чистой копии. Если каталог `corpus/` уже существует, скрипт остановится до записи документа.

```powershell
.\.venv\Scripts\python.exe -c "from docx import Document; from evidence import FILES, ROOT; folder = ROOT / 'corpus'; folder.mkdir(); doc = Document(); doc.add_paragraph('Демонстрационный журнал хранится в учебном архиве.'); doc.save(folder / FILES['ib-project'])"
.\.venv\Scripts\python.exe evidence.py index
.\.venv\Scripts\python.exe evidence.py search "журнал" --limit 1
```

Индекс появится в `data/evidence.sqlite3`. Сообщения об остальных трёх отсутствующих файлах ожидаемы. В результате поиска проверьте поля `locator` (значение `p1`), `text` (учебный абзац) и `applicability` (значение `unknown`). Для этой проверки Ollama не нужна.

### 3. Подготовьте модель Ollama

Если локальный сервер Ollama ещё не запущен, откройте отдельный терминал, выполните `ollama serve` и оставьте его открытым. В терминале проекта выполните команды:

```powershell
ollama pull qwen2.5:1.5b
ollama list
$env:CEA_OLLAMA_MODEL = 'qwen2.5:1.5b'
```

Убедитесь, что тег модели появился в списке. Это также модель по умолчанию для Streamlit. Для другой локальной модели укажите её установленный тег в `CEA_OLLAMA_MODEL` до запуска приложения.

### 4. Откройте интерфейс

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте локальный адрес из вывода Streamlit. Проект привязывает интерфейс к `127.0.0.1`. Caddy и Tailscale для локального запуска не нужны.

## Три сценария для проверки

1. **Ответ с проверяемым источником.** Спросите «Где хранится демонстрационный журнал?». Раскройте «Проверяемые основания» и сверьте имя файла и абзац `p1` с учебным DOCX. Даже если модель успешно выбрала и проверила цитату, свежий индекс даёт `NEEDS_REVIEW`: применимость документа ещё не подтверждена. Для `ANSWERED` нужны также статус применимости `confirmed` и заполненное основание подтверждения. Если модель не находит прямого ответа, возможен `NO_EVIDENCE`.
2. **Уточнение области.** Спросите «Можно ли начать работы до подписания договора?». Агент сначала предложит выбрать процесс и дирекцию. После выбора он проверит исходный вопрос в пределах указанного документа. Если выбрать «Не могу определить область», интерфейс позволяет передать нерешённый вопрос эксперту.
3. **Эскалация и повторное использование FAQ.** В учебном корпусе спросите «Где получить демостенд?». Нажмите «Передать в службу качества» и запомните номер обращения. Оно сохраняется в `data/quality.sqlite3` даже при выключенной почте. Во втором терминале из корня той же копии выполните команды ниже. Введите номер, показанный интерфейсом.

```powershell
$ticket = Read-Host 'Номер обращения'
.\.venv\Scripts\python.exe quality.py list
.\.venv\Scripts\python.exe quality.py show $ticket
.\.venv\Scripts\python.exe quality.py approve $ticket --expert demo --answer "Обратитесь к оператору учебной площадки."
```

Повторите «Где получить демостенд?» в той же области. Ожидаемый результат — статус `FAQ`, пометка «Утверждённый ответ службы качества» и введённый оператором текст. Ключ совпадения включает область и вопрос с учётом регистра и пунктуации, крайние пробелы отбрасываются. Регрессионный тест проверяет и случай прямого противоречия с регламентом: FAQ возвращается без поиска, чтения фрагментов и вызова модели. Экспертный текст отображается без ссылки на регламент. См. [тесты службы качества](tests/test_quality.py).

## Исходящие уведомления SMTP

Для локального примера оставьте `CEA_SMTP_ENABLED=0`. Для отправки передайте перечисленные ниже переменные в окружение **процесса Streamlit** перед его запуском. Код читает их из окружения напрямую. Используйте секрет-хранилище среды запуска для пароля, не помещайте учётные данные в репозиторий или командную историю.

| Переменная | Значение |
|---|---|
| `CEA_SMTP_ENABLED` | Только значение `1` включает отправку. |
| `CEA_SMTP_HOST`, `CEA_SMTP_PORT` | Имя сервера и числовой порт для TLS с момента подключения (`SMTP_SSL`, порт от 1 до 65535). |
| `CEA_SMTP_LOGIN`, `CEA_SMTP_PASSWORD` | Учётные данные для аутентификации на SMTP-сервере. |
| `CEA_SMTP_FROM` | Один адрес отправителя. |
| `CEA_SMTP_TO`, `CEA_SMTP_CC` | По одному адресу службы качества и получателя копии. Адреса должны различаться. |

Для почтовых полей используйте ASCII-адреса без отображаемых имён. При передаче обращения письмо содержит его номер и вопрос сотрудника. Интерфейс отдельно показывает регистрацию обращения и состояние отправки.

**Автоматический приём входящих писем и извлечение экспертного ответа пока отсутствуют.** Оператор утверждает текст через `quality.py approve`. После этого ответ доступен для повторного использования.

## Тесты

Из корня проекта в созданном окружении выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют временные данные и подставные ответы внешних сервисов. Для прогона не нужны корпоративные документы, работающая модель или SMTP-сервер. Проверяются поиск и сверка источника, статусы применимости, уточнение, очередь, приоритет FAQ, уведомления и ограничения обработки запросов.

## Ограничения MVP

- Индексатор работает с четырьмя заданными именами DOCX. Загрузки пользовательских файлов через веб-интерфейс нет. После изменения документа повторите `evidence.py index`. CLI не предоставляет команды подтверждения применимости.
- Поиск лексический. Агент читает до трёх фрагментов, а модель, составляющая черновик, также участвует в его проверке. Полнота ответа зависит от найденного текста и результата проверки.
- Вопрос ограничен 600 символами. Уточнение предусмотрено для сценария начала работ до подписания договора. Свободного многоходового диалога нет.
- Веб-приложение допускает один одновременно обрабатываемый запрос к агенту на процесс. Бюджет вопроса — 60 секунд. Скорость ответа зависит от оборудования и модели.
